For this week's exercise I chose Option A and built a Movie Vibe Check web app using plain HTML, CSS, and JavaScript with Ollama running locally as the AI backend. I picked this option because it felt the most tangible. I wanted to actually see an LLM respond to something I built, not just read about how APIs work.
Before starting I wasn't sure how difficult setting up Ollama would be. It turned out to be more straightforward than expected. Installing it, pulling the model, and getting it running in the terminal only took a few minutes. Having that preparation done before writing any code made the whole process smoother. I think if I had jumped straight into coding without setting up Ollama first it would have felt a lot more chaotic.
The part that surprised me most was how Ollama responded. The model worked correctly from the first API call, but the output was long and full of markdown formatting : bold text, bullet points, headers. none of which displayed well in a plain HTML page. I had to rewrite the prompt several times to get clean, structured output. I also had to add a sanitization function in JavaScript to strip out any stray markdown characters the model still slipped in. I didn't expect prompt engineering to be such a hands-on part of the process.
I also ran into a CORS error early on because I was opening the HTML file directly in the browser instead of serving it through a local server. That took some debugging to figure out.
If I had more time I would add real movie posters using the TMDB API. I actually started setting up a TMDB account during this project but decided to keep the scope focused. Combining two APIs would have made the app feel much more complete and would have been a good challenge for the Complete Tier requirement.
